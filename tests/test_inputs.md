# 알고리즘 테스트 입력

데이터: `data/selected/experiment_items.csv` (1,315개). 문제: 단백질 합 >= protein_min_g, kcal_min <= 열량 합 <= kcal_max, 상품은 0개 또는 1개, 가격 합 최소.

정수화: 단백질은 g 단위 내림, 열량은 kcal 단위 반올림 (algorithms/common.py load_items). 새 알고리즘도 같은 규칙을 써야 정답이 맞는다.

정답은 DP와 B&B로 구하고 둘이 같은지 확인했다. 상품 20개 이하는 완전탐색과도 같았다. 상품 목록(item_id)과 정답 조합은 `tests/test_inputs.json`에 있다.

## 입력별 설명

**T1 작은 입력 (정답 손으로 확인용)** — 상품 10개라 2^10 = 1,024가지를 모두 따져 정답을 확인할 수 있다. 새 알고리즘의 첫 테스트로 쓴다.
- 정답 조합 예: CJ)닭가슴살통살페퍼100g ×3 (2+1) → 9,000원, 단백질 66g, 375kcal (같은 가격의 다른 조합이 있을 수 있다)

**T2 Greedy가 크게 비싼 답** — Greedy는 1g당 가장 싼 단백질 음료 3개 묶음(단백질 75g)을 사서 20g 목표를 크게 넘긴다. 최적은 해바라기씨 하나다. 이 목록에서 Greedy와 최적의 차이가 가장 크다.
- 정답 조합 예: 챠챠)해바라기씨오리지널 → 2,000원, 단백질 21g, 465kcal (같은 가격의 다른 조합이 있을 수 있다)

**T3 Greedy가 해를 못 찾음** — 해가 있는데도 Greedy는 1g당 싼 상품으로 열량을 먼저 써 버려 단백질을 못 채운다. 최적 보장 알고리즘만 답을 낸다.
- 정답 조합 예: CJ)닭가슴살통살페퍼100g ×3 (2+1) + 오뚜기)뿌셔뿌셔바베큐맛 → 10,500원, 단백질 74g, 790kcal (같은 가격의 다른 조합이 있을 수 있다)

**T4 DP만 느림 (Greedy·B&B는 금방)** — R과 C_max가 커서 DP 표가 (80+1) x (1000+1)칸이다. 상품 1,315개를 곱하면 1억 칸 이상을 계산한다. 같은 입력에서 Greedy도 최적을 찾고 B&B는 노드 몇 개로 끝난다.
- 정답 조합 예: 대상)뉴케어올프로틴초코 ×3 (2+1) → 6,600원, 단백질 122g, 630kcal (같은 가격의 다른 조합이 있을 수 있다)

**T5 B&B가 가장 많이 탐색** — 기존 실험 230개 경우 중 B&B 방문 노드가 가장 많았던 입력이다. 가지치기가 잘 안 되는 경우를 보여 준다.
- 정답 조합 예: 남양)맛있는두유검은콩190 ×2 (1+1) + 풍림)햄치즈계란구이125g + 한양)꽃보다오징어소프트 → 23,200원, 단백질 80g, 774kcal (같은 가격의 다른 조합이 있을 수 있다)

**T6 해 없음 (B&B는 증명에 노드가 많이 듦)** — 조건을 만족하는 조합이 없다. 새 알고리즘이 '해 없음'을 제대로 내는지 확인한다. B&B는 해가 없다는 걸 증명하려고 노드를 1만 개 가까이 방문한다(그래도 DP보다는 빠르다).

**T7 열량 범위가 아주 좁음** — 열량을 20kcal 범위에 맞춰야 한다. 단백질만 보고 고르는 Greedy가 범위를 맞추기 어렵다.
- 정답 조합 예: 대상)뉴케어프로초코350ml + 에스디씨)990체다치즈볼 → 4,890원, 단백질 44g, 605kcal (같은 가격의 다른 조합이 있을 수 있다)

**T8 열량 하한이 큼 (단백질은 쉬움)** — 단백질 20g은 쉽지만 열량 900kcal 이상을 싸게 채워야 한다. Greedy는 단백질용으로 음료 묶음을 먼저 사고, 2단계에서 열량을 채우려 과자를 더 산다. 최적은 볶음땅콩 하나로 둘 다 채운다.
- 정답 조합 예: 영광C)볶음땅콩150g → 2,700원, 단백질 40g, 918kcal (같은 가격의 다른 조합이 있을 수 있다)

**T9 중간 크기 (과제 강조 구간 n = 50)** — 과제에서 강조한 n = 30~50 구간의 대표 입력이다. 모두 최적을 찾지만 DP만 시간이 크게 든다.
- 정답 조합 예: 매일)셀렉스프로핏밀크250 ×3 (2+1) + 팔도)김치도시락 → 7,000원, 단백질 66g, 700kcal (같은 가격의 다른 조합이 있을 수 있다)

## 쓰는 방법

1. `tests/test_inputs.json`의 `input`을 읽는다. `items`가 `"all"`이면 CSV 전체, 아니면 item_id 목록의 상품만 쓴다.
2. 내 알고리즘의 가격 합을 `answer.optimal_cost`와 비교한다. 최적 보장 알고리즘이면 같아야 하고, 근사·휴리스틱이면 차이(%)를 적는다.
3. 시간은 컴퓨터마다 달라서, 같은 컴퓨터에서 Greedy·DP·B&B와 함께 재서 비교한다.

> 시간(ms)은 i5-1340P 노트북 1회 측정값이라 참고용이다. 비교에는 dp_updates, bnb_nodes 같은 횟수가 더 안정적이다.

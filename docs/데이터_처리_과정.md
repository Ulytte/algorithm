# 데이터 처리 과정

CU 상품 4,233개에서 실험용 1,315개가 나오기까지의 단계를 정리한다. 숫자는 모두 각 단계의 출력 파일에서 센 값이다(2026-11-24 수집 기준).

## 2. 매칭 등급 (③)

| 등급 | 기준 | 개수 | 실험에 사용 |
|---|---|---|---|
| A | 이름 비슷 + 브랜드 일치 + 용량 일치 | 387 | 사용 |
| B | 이름 비슷 + 브랜드 일치, 용량이 달라 100g(ml)당 값 × CU 용량으로 환산 | 274 | 사용 |
| B- | 이름 비슷 + 브랜드 문제 없음, CU 상품명에 용량이 없어 DB 중량을 그대로 사용 (같은 규격이라고 가정) | 834 | 사용 **[검증 필요]** |
| C | 후보만 있음 | 2,300 | 안 씀 |
| F | 후보 없음 | 438 | 안 씀 |

매칭 규칙 (파일럿에서 사람이 100개를 확인하며 찾은 오매칭을 막는 규칙):
- 다른 제조사 제품과 연결되지 않게 CU 브랜드 접두어(예: `하림)`)를 DB 제조사·상품명에서 확인한다.
- 용량이 다르면 100g(ml)당 값으로 환산한다.
- CU 카테고리와 DB 분류가 충돌하면 감점한다(예: 음료 ↔ 빙과).
- 열량 ≈ 4×단백질 + 4×탄수화물 + 9×지방으로 검산하고, 어긋나면 등급을 낮춘다.

**영양값 계산**: DB 값은 기준량(보통 100g)당이므로 `상품 1개 값 = 기준량당 값 × 상품 중량 ÷ 기준량`으로 바꾼다.
- 예: 하림 마늘후랑크는 100g당 236kcal이고 CU 용량이 70g이므로, 236 × 70 ÷ 100 = 165.2kcal

## 3. 실험에서 뺀 상품 (⑤, 169개)

목록은 `data/selected/experiment_items_excluded.csv`에 이유와 함께 있다.

| 이유 | 개수 | 예 |
|---|---|---|
| 값 이상 (자동 규칙) | 49 | 몽뜨 옥수수칩: DB가 494g 대용량 기준이라 1봉지가 2,440kcal로 계산됨 |
| 값 오류 (사람이 검토) | 16 | 분말·원액 기준 값, 다른 제품과 매칭된 경우 |
| 가스레인지 조리 필요 | 60 | 편의점에서 바로 먹을 수 없음 (전자레인지 조리는 허용) |
| 조미료·식재료 | 29 | 한 끼 식품이 아님 |
| 묶음 상품 | 15 | 햇반 210g×6입 등 |

자동 규칙(값 이상 의심):
- 1개 열량이 1,500kcal를 넘음
- 음료인데 1ml당 1kcal를 넘음
- DB 중량 기준인데 그 중량이 400g(ml)을 넘음
- 단백질 열량(4kcal/g)이 총열량보다 큼

## 4. 행사 상품 처리 (⑤·⑥)

| 행사 | 실험용 (experiment_items.csv) | 웹 앱용 (web_items.csv) |
|---|---|---|
| 없음 (876개) | 1행 | 1행 |
| 1+1 (161개) | 2개 묶음 1행: 1개 값에 영양 ×2 | 묶음 행 + 1개 행 |
| 2+1 (278개) | 3개 묶음 1행: 2개 값에 영양 ×3 | 묶음 행 + 1개 행 + 2개 행 |

웹 앱에서는 같은 상품의 행들이 한 조합에 동시에 들어가지 못하게 막는다(`group_id`가 같은 행).

## 6. 실험용 파일 주요 열 (experiment_items.csv)

| 열 | 뜻 |
|---|---|
| item_id | 상품 번호. 행사 묶음은 `번호-개수` (예: 21638-2) |
| group_id | 원래 상품 번호 (같은 상품의 행끼리 같음) |
| cu_name | CU 상품명 (행사 묶음은 `×개수 (행사)`가 붙음) |
| food_type | 식품 유형 16가지 (도시락, 닭가슴살·육가공 등) |
| units, event | 받는 개수, 행사 종류 |
| price, unit_price | 이 행을 살 때 내는 돈, 1개당 값 |
| kcal, protein_g, carb_g, fat_g, sugar_g, sodium_mg | 이 행 전체의 영양값 |
| grade, basis | 매칭 등급, 영양값 기준(CU용량 / DB식품중량) |
| mfds_name, mfds_code, maker | 연결된 식약처 DB 제품명·코드·제조사 |
| collected_at | 수집 날짜 |

알고리즘에 넣을 때는 단백질을 g 단위로 내리고, 열량을 kcal 단위로 반올림한다(`algorithms/common.py`). DP가 정수 상태를 쓰기 때문이고, 세 알고리즘이 모두 같은 값을 쓴다.

## 7. 남은 확인

- **[검증 필요]** 실험용 1,315개 중 B- 등급 729개(55%)는 '같은 규격' 가정에 기대고 있다. 최적 조합에 자주 나오는 상품부터 매장에서 포장지로 확인할 것을 제안한다. 자주 나오는 순서는 `data/selected/audit_optimal.txt`에 있다.
- 행사는 보통 매월 바뀐다. 가격과 행사는 2026-11-24 기준이다.

단백질은 채우고,
지갑은 덜 비우는 편의점 조합

운동하는 대학생이 단백질 최소량과 칼로리 범위를 입력하면, CU에서 파는 상품 중 조건을 만족하면서 총 가격이 가장 싼 조합을 찾아줍니다. 같은 문제를 알고리즘 세 개로 풀고 성능을 비교하는 프로젝트예요.

“단백질 많은 거 하나”가 아니라 “조합”을 찾는 문제

하나씩 보면 좋은 상품도, 같이 담으면 칼로리를 넘기거나 오히려 비싸질 수 있어요.

01 / REAL

실제 상황에서 나온 문제

운동 후 편의점에서 단백질은 채우고 싶은데 돈은 아끼고 싶고, 칼로리는 너무 많아도 적어도 안 되는 상황입니다.

02 / COMBINATION

여러 상품의 조합

상품마다 담을지 말지 두 가지 선택이 있어서, 상품이 50개면 가능한 조합이 2⁵⁰개(약 1,000조 개)입니다. 전부 확인할 수 없어요.

03 / TWO-SIDED

칼로리는 위아래로 묶임

단백질은 “이상”이지만 칼로리는 “최소~최대” 범위입니다. 이 양쪽 제약 때문에 단순한 방법이 자주 틀립니다.

04 / COMPARE

같은 문제, 세 가지 풀이

빠르지만 틀릴 수 있는 방법과, 정확하지만 비용이 드는 방법 두 가지를 같은 입력으로 비교합니다.

목표   총가격 Σ pᵢ·xᵢ 를 최소화
조건   단백질 Σ rᵢ·xᵢ ≥ R
         칼로리 Cmin ≤ Σ cᵢ·xᵢ ≤ Cmax
         xᵢ ∈ {0, 1} (상품 i를 담으면 1, 안 담으면 0)
한 줄 요약: 제약이 두 개 붙은 0/1 배낭 문제의 변형입니다. 수업에서 배운 Greedy · 동적계획법 · 분기한정법을 실제 데이터에 적용하고 비교하기 좋은 구조예요.

조건을 바꿔 보면서 세 알고리즘 결과 비교하기

가상 상품 8개로 실제 알고리즘을 이 페이지에서 바로 돌립니다. 슬라이더를 움직이면 결과가 다시 계산돼요.

세 알고리즘을 그림으로 이해하기

기본 조건(단백질 40g, 400~700kcal)과 가상 상품 8개로 설명합니다. Greedy는 빠르게 고르고, DP는 표를 채워 정답을 찾고, 분기한정법은 가망 없는 경우를 잘라내며 정답을 찾습니다.

01

Greedy · 가성비 순서로 담기

단백질 1g이 가장 싼 상품부터 담으면 되지 않을까?

단백질 1g당 가격 (낮을수록 먼저 담음)
1단계가성비 1·2위 닭가슴살 + 단백질음료로 단백질 43g 달성
2단계칼로리가 280kcal로 부족 → 칼로리가 싼 삼각김밥 추가
결과6,600원. 정답 5,500원보다 1,100원 비쌈

장점: 정렬 한 번이면 끝나서 매우 빠름 (O(n log n)). 한계: 처음 고른 상품을 되돌리지 않아서 최저가를 보장하지 못하고, 조건이 빡빡하면 정답이 있는데도 “조합 없음”을 낼 수 있어요. 이 실패 사례를 실제 데이터로 분석하는 게 프로젝트의 첫 단계입니다.

02

동적계획법 (DP) · 표를 채워서 정답 찾기

“단백질 x g, 칼로리 y kcal를 만드는 가장 싼 값”을 표에 적어 둔다면?

표의 각 칸 = 그 단백질·칼로리 구간을 만드는 최저 가격 (가상 상품 8개로 계산, 보기 좋게 10g·100kcal 단위로 묶음)

핵심: 상품을 하나씩 추가하면서 표를 갱신하고, 초록 영역(단백질 40g 이상 · 400~700kcal) 중 가장 싼 칸이 정답입니다. 단백질은 목표 R을 넘으면 R칸에 모아서 표 크기를 줄여요. 한계: 표 크기가 (R+1)×(Cmax+1)이라 조건이 커지면 메모리가 늘어나고, 소수점 영양값은 정수로 바꿔야 합니다.

03

분기한정법 (Branch & Bound) · 가망 없는 가지 자르기

지금까지 찾은 최저가보다 비싸질 게 뻔한 경우는 더 볼 필요 없지 않을까?

“담는다 / 안 담는다”로 갈라지는 탐색 트리 (개념도)
-분기한정법이 실제로 방문한 노드
-전부 다 보는 완전탐색 트리의 노드

하한(bound): “지금 가격 + 부족한 단백질 × 남은 상품 중 가장 싼 1g당 가격”. 이 값이 이미 찾은 최저가보다 크면 그 가지 아래는 볼 필요가 없어요. 트리의 숫자는 설명용이고, 아래 방문 노드 수는 가상 상품 8개로 이 페이지에서 직접 계산한 값입니다. 한계: 자르지 못하는 입력에서는 상품 수가 늘수록 시간이 급격히 늘 수 있습니다.

알고리즘최저가 보장속도메모리약점
Greedy✗매우 빠름적음칼로리 범위 때문에 오답·거짓 실패
동적계획법✓조건 크기에 비례표 크기만큼 큼조건이 커지면 메모리 증가
분기한정법✓입력에 따라 크게 다름적음최악의 경우 지수 시간

작게 만들고, 문제를 찾고, 개선하기

교수님이 강조하신 “기본 구현 → 문제점 분석 → 개선 → 비교” 순서를 그대로 따릅니다.

1

실제 CU 상품 데이터 확보

상품명·가격은 CU 공식 사이트, 칼로리·단백질은 포장지 영양성분표와 식약처 영양DB로 확인합니다. 행사가는 빼고 정상가를 씁니다.

2

Greedy 구현 + 실패 사례 분석

어떤 조건에서 최저가를 놓치는지, 정답이 있는데 “조합 없음”을 내는지 실제 데이터로 찾습니다.

3

DP 구현으로 정확한 최적해

Greedy의 한계를 해결하고, 표 크기·메모리가 조건에 따라 어떻게 늘어나는지 측정합니다.

4

분기한정법 구현으로 메모리 문제 개선

DP와 같은 정답을 내는지 교차 검증하고, 가지치기가 얼마나 효과적인지 봅니다.

5

같은 입력으로 비교실험

최적해 대비 가격 차이, 해를 못 찾은 비율, 실행시간, 메모리를 상품 수와 조건의 엄격함을 바꿔 가며 반복 측정합니다.

공정한 비교: 세 알고리즘 모두 같은 상품 데이터, 같은 제약조건, 같은 목적함수를 씁니다. 작은 규모에서는 완전탐색으로 정답을 확인하고, 데이터 로딩 시간과 알고리즘 실행 시간은 따로 잽니다.

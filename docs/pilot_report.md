# 파일럿: CU 상품 ↔ 식약처 영양DB 자동 매칭률 (2026-11-23)

## 무엇을 했나
1. `scripts/collect_cu.py` — CU 공식 사이트에서 간편식사·즉석조리·식품·음료 상품 **2,874개** 수집
   (상품명, 가격, 바코드, 행사배지, 출처 URL, 수집일) → `data/raw/cu_products.csv`
2. `scripts/match_mfds.py` — 단백질 관련 후보 721개 중 무작위 100개(간편식사 40 / 식품 30 / 음료 30, seed 고정)를
   공공데이터포털 '전국통합식품영양성분정보(가공식품)' 조회 화면에 상품명으로 질의해 자동 매칭
   → `data/pilot/pilot_match.csv`, `data/pilot/pilot_summary.txt`

## 결과 (실측)
| 구분 | n | 확실 | 추정 | 실패 |
|---|---|---|---|---|
| 간편식사 | 40 | 0 | 23 | 17 |
| 식품 | 30 | 2 | 18 | 10 |
| 음료 | 30 | 2 | 11 | 17 |
| **전체** | **100** | **4** | **52** | **44** |

- 확실 = 상품명 유사 + 브랜드 일치 + **중량 일치**
- 추정 = 이름만 비슷함 → 사람이 검증해야 함. 추정 52개 중 11개(식품 6, 음료 5)는 CU 표기 용량과 DB 중량이 다름(묶음/다른 규격). 간편식사는 CU 상품명에 용량 표기가 없어 이 검사를 할 수 없음

## 수동 검토에서 확인된 오매칭 유형 (1차 기준으로 '추정/확실'이었던 것)
- 다른 제품: `서울)흰우유300ml` → '흰우유콘'(아이스크림), `서울)멸균우유200ml` → 폴란드 수입 멸균우유 1000ml
- 다른 제조사: `진주햄)천하매콤후랑크70g` → 하림 제품 (중량만 우연히 일치)
- 묶음 단위: `흥생)구운계란3입` → 1050g 대용량 → 1개 환산 시 1596kcal (명백한 오류)
- 맛/규격 차이: 테이크핏 프로틴 초코 → '맥스 초코맛', 불닭볶음면 소컵 → 봉지면 140g

## 결론
- **자동 매칭만으로 실험 데이터를 만들 수 없다.** 신뢰 가능한 자동 매칭은 100개 중 4개.
- 간편식사(도시락·김밥·삼각김밥)는 상품명이 DB와 정확히 같은 경우가 많지만(제조사 비지에프푸드·푸드플래닛 등),
  CU 상품명에 중량이 없어 같은 제품인지 확정할 수 없다 → **매장 포장지 확인 필요**.
- 자동 매칭은 '후보 생성기'로만 쓰고, 최종 값은 포장지 영양성분표(사진)로 확정한다.

## 제안: 데이터셋 확정 절차
1. 목표 40~50개 선정: 확실 4개 + 추정 후보 중 단백질 기여도가 큰 상품 + 매칭 실패지만 꼭 필요한 상품(닭가슴살, 계란, 단백질음료 등)
2. 팀원이 CU 매장에서 포장지 영양성분표 촬영 (상품명, 총 내용량, 1개 기준 kcal·단백질, 매장 판매가 확인)
3. 사진 파일명과 함께 `data/final/cu_dataset.csv`에 기록, 출처 컬럼에 '포장지(촬영일)' 또는 '식약처DB(식품코드)' 표기
4. 자동 검사: 단백질(g) ≤ 내용량(g), kcal ≈ 4×탄수 + 4×단백질 + 9×지방 (±15%) 위반 시 재확인

## 한계
- 공공데이터포털 조회 화면은 질의당 첫 페이지(최대 약 45건)만 반환 → 흔한 이름(예: '우유')은 정답이 누락될 수 있음
- 표본은 키워드 필터로 고른 '단백질 관련' 상품이며, CU 전체 상품의 매칭률을 대표하지 않음
- 확실/추정/실패 기준은 휴리스틱이며, 수동 검토는 1인이 수행

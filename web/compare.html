목표min Σ pᵢ·xᵢ
단백질Σ rᵢ·xᵢ ≥ R
칼로리Cmin ≤ Σ cᵢ·xᵢ ≤ Cmax
선택xᵢ ∈ {0, 1}
  • pᵢ 가격(원), rᵢ 단백질(g), cᵢ 칼로리(kcal). 상품마다 최대 1개를 고릅니다.
  • 1+1, 2+1 행사 상품은 묶음 한 행입니다. 예를 들어 2+1은 2개 값에 3개, 영양도 3배입니다.

  • 조건을 만족하는 조합이 없으면 '해 없음'을 돌려줍니다. 세 알고리즘은 같은 입력과 같은 조건을 씁니다.

세 알고리즘

V1. Greedy

단백질 1g당 가격이 싼 상품부터 담고, 칼로리가 모자라면 1kcal당 싼 상품을 더 담습니다. 한 번 담은 상품은 빼지 않습니다.

정렬: 가격/단백질 오름차순
for 상품 in 정렬순:
  if 단백질 ≥ R: break
  if 칼로리 + c ≤ Cmax: 담기
칼로리 < Cmin 이면
  가격/칼로리 순으로 더 담기
시간
O(n log n)
공간
O(n)
최적
보장 안 됨
  • 가장 빠르고 구현이 쉽습니다.
  • 더 비싼 조합을 내거나, 해가 있는데도 못 찾을 수 있습니다.

V2. DP

dp[p][k]는 단백질 p와 칼로리 정확히 k를 만드는 최소 가격입니다. 단백질은 R에서 자릅니다. R 이상은 모두 R로 봅니다.

dp[0][0] = 0, 나머지 ∞
for 상품 (r, c, 가격):
  for p, k (뒤에서부터):
    dp[min(R, p+r)][k+c] =
      min(…, dp[p][k] + 가격)
답 = min dp[R][k], Cmin ≤ k ≤ Cmax
시간
O(n · R · Cmax)
공간
O(R · Cmax) + 역추적 기록
최적
보장 (정수 값 기준)
  • n이 커져도 시간이 n에 비례합니다.
  • R, Cmax가 크면 표가 커집니다. 영양 조건이 하나 늘 때마다 차원이 하나 늘어납니다.

V3. Branch and Bound

단백질 1g당 싼 순서로 상품마다 '넣기/안 넣기' 두 갈래로 나눕니다. 이 갈래로 낼 수 있는 가장 싼 값(하한)이 지금 최선보다 비싸면 버립니다.

최선 = Greedy 해
dfs(i, 가격, p, k):
  if p ≥ R and k ≥ Cmin: 최선 갱신
  if 하한(i) ≥ 최선: return
  넣기 (k+c ≤ Cmax 일 때)
  안 넣기
하한 = 가격 + max(분수 배낭 단백질 비용,
                  모자란 칼로리 × 최저 1kcal 값)
시간
최악 O(2ⁿ)
공간
O(n) (재귀 깊이)
최적
보장 (제한 안에 끝나면)
  • 하한이 잘 맞으면 대부분의 갈래를 일찍 버립니다.
  • 최악에는 지수 시간입니다. 30초 제한에 걸리면 '최적 보장 안 됨'으로 기록합니다.
